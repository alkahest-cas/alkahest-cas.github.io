Python API

Simplification API

Alkahest provides two simplification engines: a fast rule-based engine and an e-graph (equality saturation) engine. Domain-specific rule sets are also available.

#Rule-based simplification

DerivedResult

#Constant folding, special values and zero recognition

Every simplifier entry point (simplify(), simplify_trig(), simplify_egraph(), simplify_log_exp(), simplify_trig_normal_form(), simplify_expanded()) folds exact special values — sin/cos/tan at rational multiples of pi with denominator 1, 2, 3, 4 or 6, sin(n*pi) = 0 and cos(n*pi) = (-1)**n for an Integer-domain n, exp(I*pi*q), inverse trig at the standard values, gamma at half-integers, erf(0), dilog(0, 1, -1, 1/2) — radical powers (sqrt(2)**2 = 2, sqrt(8) = 2*sqrt(2), sqrt(x)**2 = x for a provably non-negative x), I**2 = -1 inside products, cancelling exponentials (exp(-x)*exp(x) = 1), and replaces any sum that is identically zero by 0 (see is_zero(); the step records d != 0 for every denominator d it cleared).

function 
is_zero(expr: Any, *, assumptions: Any=None) → bool | None
#source

Decide whether expr is identically zero on its symbols' domains.

Parameters
exprExpr or DerivedResult
assumptionsAssumptions, optional

Extra facts (x > 0, x != 0, …). Defaults to the active alkahest.context(assumptions=...), if any. Symbol domains (Domain.Positive, Domain.Integer, …) always apply.

Returns
bool or None

True only when proved by exact symbolic reasoning; False when proved non-zero (exactly, or by a rigorous Arb ball at an admissible point); None when undetermined. Use equals() to see the provenance (status, method, evidence).

Examples
Python
>>> p = ExprPool(); x = p.symbol("x")
>>> is_zero(sin(x)**2 + cos(x)**2 - 1)
True
>>> is_zero(sin(x) - x)
False

function 
to_real_form(expr, assumptions=None)
#source

alkahest.to_real_form(expr, assumptions=None) -> Expr

Rewrite expr into an equal expression with no imaginary unit and no square root of a negative quantity: exp(±i·θ) pairs become cos/sin, exp(a ± √(−b)) with b > 0 becomes e^a·(cos √b ± i sin √b), cosh(i·x) becomes cos x, and perfect squares leave square roots (√(c²·k) → |c|·√k, → c·√k once c ≥ 0 is known). The real part is returned only when the imaginary part is proved identically zero; otherwise expr comes back unchanged. Free symbols must be real (any domain but Complex).

Parameters
expr

the expression to rewrite.

assumptions

optional Assumptions (k > 0, a >= 0…); the active alkahest.context(assumptions=...) and symbol domains always apply.

Returns
Expr

an equal expression, real-valued where it could be proved so.

Examples
Python
>>> p = ExprPool(); a = p.symbol("a")
>>> to_real_form(sqrt(4*a**2))
(2 * abs(a))
function 
rewrite_piecewise(expr)
#source

alkahest.rewrite_piecewise(expr) -> Expr

Lower abs, sign, heaviside, min and max to piecewise(), everywhere in expr.

abs(g) becomes Piecewise((g >= 0, g); -g); min(a, b) becomes Piecewise((a <= b, a); b) and max(a, b) the >= form (more than two arguments fold to the right); sign and heaviside use their registry values at 0 (0 and 1/2). The lowered form agrees with the original at every point. floor/ceil/round have infinitely many pieces and are left alone. integrate() applies this itself.

Examples
Python
>>> p = ExprPool(); x = p.symbol("x")
>>> rewrite_piecewise(abs(x))
Piecewise((x >= 0, x); -x)

#Parallel simplification

All three take a single expression and return the same result as simplify(); only the schedule differs. Each requires --features parallel at build time and falls back to sequential simplify() without it, so the calls are always available. Check capabilities()["features"]["parallel"] to tell which you have.

function 
simplify_par(expr)
#source

Simplify an expression using a recursive fork-join traversal.

Requires the parallel feature at build time; without it this falls back to sequential simplify(), so the call is always available. Check alkahest.capabilities()["features"]["parallel"] to tell which you have.

Fork-join keeps each subtree on one worker, which suits wide expressions — a large sum or product of independent terms. For deep, narrow expressions prefer simplify_redex(), or let simplify_auto() choose.

The result matches simplify() exactly. The derivation log may vary in order between runs, because two workers can reach the same node concurrently; simplify_redex() does not have that property.

function 
simplify_redex(expr)
#source

Simplify an expression by scheduling independent rewrites level by level.

Requires the parallel feature at build time; without it this falls back to sequential simplify(), so the call is always available.

Nodes are bucketed by height, so every node at a given height is rewritten concurrently regardless of its type. That suits deep expressions, where simplify_par() finds no wide node to fork on and ends up running essentially sequentially. It also visits each node exactly once, so unlike simplify_par() the derivation log is deterministic — identical across runs and across CPU counts.

The result matches simplify() exactly.

function 
simplify_auto(expr)
#source

Simplify in parallel, choosing the strategy from the expression's shape.

Requires the parallel feature at build time; without it this falls back to sequential simplify(), so the call is always available.

Dispatches to simplify_par() for wide expressions when enough CPU cores are available, and to simplify_redex() otherwise. Use simplify_strategy() to see which it would pick without running it.

This is the one to reach for if you do not want to think about shape. The result matches simplify() exactly.

function 
simplify_strategy(expr)
#source

Report which strategy simplify_auto() would use for expr.

Returns "fork_join" (simplify_par()), "level_scheduled" (simplify_redex()), or "sequential" when the extension was built without the parallel feature and both parallel entry points fall back to simplify().

The answer depends on the number of worker threads available as well as the expression, so it can differ between machines.

#Pattern matching and rules

function 
make_rule(lhs, rhs, sequence=None)
#source

alkahest.make_rule(lhs, rhs, sequence=None) — create a rewrite rule from two expressions.

Symbols whose names start with a lower-case letter in lhs are wildcards that bind to any sub-expression; the same names in rhs are replaced by the bound values.

sequence lists noncommutative symbols of lhs that are sequence wildcards: in make_rule(A*X*B, ..., sequence=[X]) the symbol X matches any contiguous run of noncommutative factors between A and B (possibly empty), and X in rhs is replaced by that run. Matching is leftmost, and each sequence wildcard takes the shortest run that lets the rest match. A sequence rule only fires inside a product of at least two noncommutative factors, and applies through simplify_with (not nc_rewrite). Raises NcError E-NC-009 for a malformed pattern.

Example:

Python
rule = alkahest.make_rule(a*b + a*c, a*(b + c))  # factoring rule
result = alkahest.simplify_with(expr, [rule])
function 
match_pattern(pattern_expr, expr, *, wildcards=True)
#source

alkahest.match_pattern(pattern_expr, expr) -> list[dict[str, Expr]]

Find all AC-aware matches of pattern_expr anywhere in expr. Each match is returned as a dict mapping wildcard names to matched sub-expressions. Wildcards are symbols whose names start with a lower-case letter. Set wildcards=False to treat every symbol as a literal (e.g. when the pattern is a single variable like x).

#Rational functions

function 
apart(expr, var)
#source

Partial-fraction decomposition of expr as a rational function of var.

Decomposes p(x)/q(x) into poly_part + Σ A_ij(x) / f_i(x)**j where the f_i are the distinct ℚ-irreducible factors of the denominator and deg A_ij < deg f_i.

Parameters
exprExpr or DerivedResult

A rational function of var. DerivedResult is coerced to .value.

varExpr

The variable to decompose in.

Returns
Expr
Raises
ValueError

If expr is not a rational function of var, or denominator factorization fails.

Notes

Decomposition is over ℚ: irreducible quadratics (and higher) are kept intact, not split into complex/algebraic linear factors.

Examples
Python
>>> p = ExprPool(); x = p.symbol("x")
>>> apart(1 / (x**2 - 1), x)   # 1/(2(x-1)) - 1/(2(x+1))

#More rewriting

function 
simplify_trig_normal_form(expr)
#source

Trigonometric normal-form simplifier.

Runs the full algebraic core with bounded polynomial expansion plus the sin/cos-polynomial trig identities (argument-sign normalization and the Pythagorean identity, including its multi-angle case), driven to a fixed point. Unlike simplify_trig() (identities only, no expansion), this composes product expansion, constant folding, like-term collection, and Pythagorean reduction in a single call.

The headline use case is verifying orthogonality of a rotation (direction-cosine) matrix: every entry of R.T @ R - I collapses to 0. It reduces in the sin/cos monomial basis and does not introduce compound-angle (sin(2u), sin(u+v), …) forms. This bundle is heavier than simplify() and is opt-in.

Parameters
exprExpr or DerivedResult
Returns
DerivedResult
